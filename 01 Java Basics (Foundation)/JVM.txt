
# 🔷 JVM (Java Virtual Machine) — In Detail

## 📌 Definition

JVM is a **virtual (software-based) machine** that:

* Executes Java **bytecode**
* Converts it into **machine code**
* Provides **platform independence**

👉 It acts as a bridge between Java program and the operating system.

---

## 🔁 How JVM Works (Execution Flow)

```text
.java (source code)
   ↓ (javac compiler)
.class (bytecode)
   ↓
JVM
   ↓
Machine Code → Output
```

👉 Key idea:
**Java is compiled once, run anywhere (WORA)** because JVM is available on every OS.

---

## 🧠 Internal Architecture of JVM

JVM mainly has **3 major components**:

---

## 1️⃣ Class Loader Subsystem

👉 Responsible for loading `.class` files into memory.

### Phases:

1. **Loading**

   * Loads class file into JVM

2. **Linking**

   * **Verification** → checks bytecode safety
   * **Preparation** → allocates memory
   * **Resolution** → replaces symbolic references

3. **Initialization**

   * Executes static variables and blocks

---

## 2️⃣ Runtime Data Areas (Memory Structure)

This is **very important for exams 🔥**

### 📍 Method Area

* Stores:

  * Class metadata
  * Static variables
  * Method code

---

### 📍 Heap Area

* Stores:

  * Objects (created using `new`)
* Shared among all threads
* Managed by **Garbage Collector**

---

### 📍 Stack Area

* Stores:

  * Method calls
  * Local variables
* Each thread has its own stack

---

### 📍 PC Register (Program Counter)

* Keeps track of **current instruction**

---

### 📍 Native Method Stack

* Used for **native (non-Java) methods**

---

## 3️⃣ Execution Engine

👉 Executes the bytecode.

### Components:

### 🔸 Interpreter

* Executes bytecode line-by-line
* Slower

### 🔸 JIT (Just-In-Time Compiler)

* Converts bytecode → machine code at runtime
* Improves performance

👉 **Important:**
JIT makes Java faster after some time of execution.

---

### 🔸 Garbage Collector (GC)

* Automatically deletes unused objects from heap
* Prevents memory leaks

---

## ⚙️ Key Features of JVM

* ✔ Platform Independent
* ✔ Automatic Memory Management
* ✔ Security (bytecode verification)
* ✔ Multithreading support
* ✔ Performance optimization (JIT)

---

You can draw this:

```text
        Class Loader
              ↓

   (Heap, Stack, Method Area)
```

## 🎯 Important Viva Questions

👉 **1. What is JVM?**
Executes bytecode and provides runtime environment.

👉 **2. Why is JVM platform dependent?**
Because JVM is different for each OS, but bytecode is same.

👉 **3. What is JIT?**
Compiler that converts bytecode to machine code at runtime.

👉 **4. What is Heap vs Stack?**

* Heap → Objects
* Stack → Method calls

---

## 💡 Simple Way to Remember

👉 **JVM = Loader + Memory + Execution**
